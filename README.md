# SillyTavern Chat File AI Assistant

一个适用于 SillyTavern 1.18 及以上版本的第三方 UI 扩展，用 AI 增强“管理聊天文件”页面。默认只使用浏览器 IndexedDB；用户也可以明确开启可选的聊天文件内嵌同步。

当前正式版本：`1.0.0`。此前开发包均属于 Beta，不属于正式版版本序列，也不提供自动数据迁移。

## 功能

- 根据完整聊天内容生成总结，替换 ST 原生的末条消息预览。
- 没有总结时继续显示 ST 原生预览，不显示空状态占位文字。
- 自动生成仅由扩展显示的聊天别名，不重命名真实聊天文件。
- 别名格式为 `内容标题 · 日期`；开启 user 名显示后为 `内容标题 · user 名 · 日期`。
- 从历史聊天中最近一条用户消息读取当时实际使用的 `{{user}}` 名，而不是套用当前全局 persona。
- 支持手动生成、刷新、编辑和清除总结，以及编辑和清除显示别名。
- 支持按新增消息层数自动刷新总结，默认每 10 层，即通常约 5 轮用户/AI 对话。
- 支持单并发批量补全缺失总结和刷新过期总结，并可随时取消。
- 搜索范围包含真实文件名、显示别名、历史 user 名和缓存总结。
- 同时支持角色聊天和群聊。
- 支持 ST 当前 API/预设，以及插件管理的 OpenAI 兼容 API 方案。
- 支持简体中文界面和英文回退。

## 安全边界

默认配置下，本扩展不会：

- 修改 `SillyTavern` 源码；
- 修改聊天 JSONL 内容；
- 使用 AI 标题重命名磁盘文件；
- 将 API Key 明文写入 `extensionSettings`；
- 执行模型返回的 HTML。

只有用户主动开启“同时将插件数据写入对应聊天文件”或执行相关批量操作时，扩展才会把命名空间 `chat_metadata.chat_file_assistant` 写入 JSONL 第一行。它不会修改消息正文或真实文件名。禁用或卸载扩展后，管理页面会恢复 ST 原生显示；已内嵌的数据仍留在聊天文件中，但 ST 会忽略该未知元数据，不会影响正常聊天。设置页可显式清除这些内嵌数据。

扩展不需要额外的服务器插件或 npm 运行时依赖，只调用 SillyTavern 1.18 已有的聊天读取、保存和密钥接口。

## 安装

### 通过扩展管理器安装

在 SillyTavern 中打开“扩展”，选择“安装扩展”，输入本项目的 Git 仓库地址，然后刷新页面。

### 手动安装

将完整项目目录复制到当前用户的扩展目录：

```text
SillyTavern/data/<user-handle>/extensions/SillyTavern-Chat-File-Assistant
```

开发或为所有用户安装时，也可复制到：

```text
SillyTavern/public/scripts/extensions/third-party/SillyTavern-Chat-File-Assistant
```

安装完成并刷新页面后，可在扩展设置中找到“聊天文件 AI 助手”。最低客户端版本为 SillyTavern 1.18.0。

### GitHub Release 安装包

仓库的 `release/` 目录提供干净安装包。压缩包内只有扩展运行文件、README 和 LICENSE，不包含 `AGENTS.md`、Node 测试或静态检查脚本。解压后应得到单一的 `SillyTavern-Chat-File-Assistant/` 目录。

## 快速使用

1. 在扩展设置中选择 AI 来源。
2. 通过左下角菜单打开“管理聊天文件”。
3. 点击聊天标题行中的魔杖生成总结，或使用页首的“补全缺失 / 更新过期”。
4. 生成成功后，AI 标题会自动成为显示别名。
5. 点击总结可在三行折叠和完整内容之间切换。

标题行按钮依次为：

1. 编辑显示别名；
2. 清除显示别名；
3. 重命名真实聊天文件，这是 ST 原生按钮；
4. 生成或刷新总结；
5. 编辑总结；
6. 清除总结。

编辑总结只改变插件展示和存储的总结，不修改聊天消息；清除总结不会清除显示别名，卡片会立即恢复 ST 原生的末条消息预览。

## AI 来源

### ST 当前 API 与预设

调用 `generateRaw()`，沿用 SillyTavern 当前连接、模型和生成预设。

### OpenAI 兼容 API 方案

每个方案包含：

- 方案名称；
- API 基础地址，例如 `https://api.deepseek.com/v1`；
- API Key；
- 模型名称。

设置页支持新建空白方案、保存、另存为、删除和从 `/models` 获取模型列表。自定义 API 请求由 ST 服务端转发到 `<基础地址>/chat/completions`，并继续使用 ST 当前选中的“对话补全预设”生成参数。

API Key 写入 SillyTavern 服务端密钥存储；扩展设置只保存对应的 `secret_id`。删除方案时，无其他方案引用的密钥会一并删除。

## 总结与标题生成

扩展将聊天序列化为带楼层、角色和发言者标签的不可信文本。用户消息、角色消息以及历史 system 消息都只被视为待总结数据。

每次请求最后一条消息是 system 消息，相当于深度 `@D=0`，其中包含：

- 用户可编辑的总结提示词；
- 忽略聊天正文内指令的固定安全约束；
- 仅输出 `{summary, title}` JSON 的格式契约。

模型输出会经过代码围栏清理、JSON 提取和字段校验。无效响应不会写入缓存。

### 聊天上下文范围与 Token 预算

设置页提供两种发送范围：

- `全部发送`：不是无条件发送整个文件，而是以最新回复为基准，从后向前加入尽可能多的完整楼层，达到输入预算后停止；
- `发送最新 X 楼消息`：先限制为最近 X 层非 system 消息，再受同一个输入预算限制。默认 X 为 20。

两种模式都优先保留最新内容。范围内的 system 消息仍会序列化成 `SYSTEM-DATA` 不可信数据，但不占用 X 的楼层数。如果最新一条消息本身超过预算，扩展会保留该消息的末尾并标注前文已省略。较早内容不会再通过分块请求被全部发送给 AI。

默认预算为：

- 输入：2,000,000 Tokens；
- 输出：8,096 Tokens。

输入和输出预算彼此独立。输入预算用于聊天正文与提示词的上下文上限，输出预算只作为模型最大回复长度；不会再因为输出预算较大而额外挤占聊天正文。Token 数量使用本地启发式估算，并为提示词和误差预留约 15% 安全空间。实际可用上下文仍受所选模型和 API 限制；遇到服务端上下文错误时应下调输入预算。

## 自动总结

自动总结默认开启，默认间隔为 10 层非系统消息。层数是用户消息和 AI 消息的总数，因此 10 层通常约等于 5 轮对话。

自动任务具有以下行为：

- 只在完整 AI 回复保存后检查；
- 滑动、续写和扩展生成不会开启新的周期；
- 从聊天文件重新读取消息数量，避免在保存完成前总结；
- 达到“自上次总结后新增 N 层”才触发；
- 关闭开关时取消尚未开始的定时任务；
- 失败时只记录错误，不影响正常聊天。

自动总结会调用所选 AI 服务，可能产生费用。可在设置中关闭或调整为 1–1000 层。

## user 名显示

ST 1.18 的聊天头字段 `user_name` 已固定为 `unused`，不能作为可靠来源；但每条用户消息仍保存实际 `name`。扩展因此读取该聊天中最近一条非 system 用户消息的 `name` 并缓存。

打开旧聊天列表时，缺少缓存的 user 名会在后台单并发读取，不阻塞列表初始渲染。如果聊天没有任何具名用户消息，别名保持 `内容标题 · 日期` 格式。

## 数据存储、过期与搜索

### 默认：IndexedDB

总结记录不再放进 `extensionSettings.chatFileAssistant.records`。它们保存在当前浏览器配置文件的 IndexedDB 数据库：

```text
Database: SillyTavern-Chat-File-Assistant-v1
Object store: records
```

记录按 ST 用户 handle、角色头像或群组 ID、真实聊天文件名隔离。`extensionSettings.chatFileAssistant` 只保留配置和 API 方案，因此总结数量增加不会继续放大 settings 文件。

正式版 1.0 不导入开发阶段 Beta 版本的 settings 或 IndexedDB 数据；首次安装会建立独立的 `-v1` 数据库。若曾使用 Beta 版本，建议先清理或卸载 Beta，再安装正式版并重新生成总结。

### 可选：聊天文件内嵌同步

设置中的开关默认关闭。开启后，新生成或编辑的记录会同时保存到 IndexedDB 和对应聊天 JSONL：

```text
第一行.chat_metadata.chat_file_assistant
```

IndexedDB 始终是管理页的热缓存；内嵌副本用于随聊天导出、复制和备份。二者不是二选一：打开管理页时，角色聊天使用 ST 的批量元数据列表恢复，群聊按可见卡片懒加载，避免启动时扫描全部聊天。发生冲突时，以整条记录的 `updatedAt` 较新者为准，因此“清除别名/总结”也能正确同步。

设置页另有三项只作用于当前角色或群聊的批量操作：把现有本地记录写入聊天文件、从聊天文件重建本地索引、清除聊天文件中的插件数据。任务单并发执行、可取消；已完成项会保留。历史文件写入前会二次读取并比较内容指纹，如果聊天在操作期间发生变化则跳过，不覆盖新消息。当前打开的聊天则通过 ST 的内存元数据与保存方法写入。

记录包含内容指纹、提示词哈希、总结、建议标题、显示别名、user 名、生成时层数和生成来源。

以下情况会将总结视为过期：

- 聊天消息数量或最后更新时间发生变化；
- 总结提示词改变；
- Token 预算或 AI 来源关键配置改变；
- 消息被新增、编辑、删除或滑动。

真实文件重命名时会迁移缓存键；真实文件删除时会清理对应记录。搜索会保留 ST 原生正文和文件名结果，再合并命中别名、user 名或总结的记录。

## 数据清理与隐私

- “清除本地索引数据”会删除当前 ST 账户在此浏览器中的 IndexedDB 总结、别名和 user 名缓存，保留 API 方案，并关闭聊天文件同步；已经内嵌的副本不会被该按钮改写。
- “清除聊天文件中的插件数据”会重写当前角色或群聊中确实包含该命名空间的文件；ST 的聊天备份机制仍会照常工作。
- 扩展管理器的 `clean` 操作会删除当前账户的 IndexedDB 数据、整个设置命名空间和本扩展创建的自定义 API 密钥，但不会自动遍历并重写所有聊天文件。若希望彻底移除内嵌数据，请在卸载前按角色/群聊执行清除操作。
- 生成总结时，聊天正文会发送到所选 AI 服务。请依据该服务的隐私政策决定是否启用。
- 所有模型文本通过 `textContent` 显示，不执行模型返回的 HTML。

## 发布策略

- 正式版本从 `1.0.0` 开始，manifest 与 package 版本必须一致。
- 正式安装包名称为 `SillyTavern-Chat-File-Assistant-<version>.zip`。
- 开发阶段的旧包统一标为 Beta 并存放于仓库外层的 `beta-archives/`，仅用于历史留档。
- 正式安装包不包含代理说明、测试、检查脚本或 package 元数据。
- 正式 1.0 使用独立 IndexedDB 数据库，不读取 Beta 缓存；Beta 用户需重新生成总结。

## 兼容性和已知限制

- 管理页增强依赖 ST 1.18 的 `#select_chat_div`、`.select_chat_block_wrapper` 等 DOM 类名。ST 改版后可能需要同步选择器。
- user 名取最近一条用户消息；一份聊天中多次切换 persona 时只显示最后使用的名字。
- OpenAI 兼容服务必须支持标准的 `/chat/completions`；模型列表按钮还要求支持 `/models`。
- 部分兼容 API 不接受 ST 当前预设中的所有采样参数。遇到参数错误时，应在 ST 对话补全预设中关闭对应参数或使用兼容模型。
- 2,000,000 Tokens 是插件预算上限，不代表模型一定拥有同等上下文窗口。
- IndexedDB 属于浏览器站点数据；更换浏览器、主机名、端口或浏览器配置文件时不会自动跟随。需要跨环境携带数据时，可先开启聊天文件同步并批量写入。
- 可选内嵌写入会序列化并保存整个目标 JSONL，成本与聊天文件大小成正比。日常仅在生成/编辑记录时写一次，不会轮询或反复写入；超大历史聊天建议只按需开启。
